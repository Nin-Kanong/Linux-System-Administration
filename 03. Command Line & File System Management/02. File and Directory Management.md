File and Directory Management — Linux





This lesson covers how to create, view, navigate, copy, move, rename, delete, and manage files and directories in Linux.

It applies to Ubuntu, Kali Linux, Debian, and most other Linux distributions.

## 1. Understanding Files and Directories

In Linux:

- File: Stores information, such as text, images, programs, scripts, and configuration.
- Directory: A container used to organize files and other directories.
- Filesystem: The structure Linux uses to store and organize data.

Example directory structure:

```
/home/k4n0ng/
│
├── Documents/
│   ├── notes.txt
│   └── report.pdf
│
├── Downloads/
│   └── tool.zip
│
├── Pictures/
│   └── image.png
│
└── Scripts/
    ├── scan.py
    └── backup.sh
```

### Important Linux paths

| Path    | Description                                                               |
| ------- | ------------------------------------------------------------------------- |
| `/`     | Root directory; the starting point of the Linux filesystem                |
| `/home` | Contains users' home directories                                          |
| `/root` | Home directory of the root account                                        |
| `/etc`  | System configuration files                                                |
| `/var`  | Variable data, logs, and application data                                 |
| `/tmp`  | Temporary files                                                           |
| `/usr`  | User applications, libraries, and shared resources                        |
| `/opt`  | Optional third-party applications                                         |
| `/bin`  | Essential user commands (commonly linked to `/usr/bin`)                   |
| `/sbin` | Essential system administration commands (commonly linked to `/usr/sbin`) |
| `~`     | Current user's home directory                                             |
| `.`     | Current directory                                                         |
| `..`    | Parent directory                                                          |

## 2. Absolute Path vs Relative Path

Linux supports two main ways to specify a file or directory location.

Absolute path

An absolute path starts from the root directory `/`.

Example:

```
/home/k4n0ng/Documents/notes.txt
```

Relative path

A relative path starts from your current working directory.

Example: Suppose your current location is:

```
/home/k4n0ng/
```

You can access the file using:

```
Documents/notes.txt
```

| Type              | Example               | Description                              |
| ----------------- | --------------------- | ---------------------------------------- |
| Absolute path     | `/home/user/file.txt` | Starts from `/`                          |
| Relative path     | `Documents/file.txt`  | Starts from the current directory        |
| Current directory | `.`                   | Represents your current location         |
| Parent directory  | `..`                  | Represents the directory one level above |
| Home directory    | `~`                   | Represents your user's home directory    |

## 3. Navigating Directories

### 3.1 `pwd` — Print Working Directory

Displays your current location.

Syntax:

```
pwd
```

Example:

```
$ pwd
/home/k4n0ng
```

### 3.2 `cd` — Change Directory

Used to move between directories.

Syntax:

```
cd [directory]
```

| Command    | Description                                 |
| ---------- | ------------------------------------------- |
| `cd /home` | Move to `/home`                             |
| `cd /etc`  | Move to `/etc`                              |
| `cd ..`    | Move one directory backward (to the parent) |
| `cd ../..` | Move two levels up                          |
| `cd ~`     | Move to your home directory                 |
| `cd`       | Move to your home directory                 |
| `cd -`     | Return to the previous working directory    |
| `cd .`     | Stay in the current directory               |

Example:

```
$ pwd
/home/k4n0ng

$ cd Documents

$ pwd
/home/k4n0ng/Documents

$ cd ..

$ pwd
/home/k4n0ng
```

### 3.3 Navigating with Multiple Directories

You can navigate directly to a nested directory.

```
cd /home/k4n0ng/Documents/Projects
```

You do not have to enter each directory separately.

## 4. Listing Files and Directories

### 4.1 `ls` — List Directory Contents

Displays files and directories in the current location.

Syntax:

```
ls [options] [directory]
```

| Command    | Description                                      |
| ---------- | ------------------------------------------------ |
| `ls`       | List files and directories                       |
| `ls /home` | List contents of `/home`                         |
| `ls -l`    | Display detailed information                     |
| `ls -a`    | Show hidden files and directories                |
| `ls -la`   | Show all files in detailed format                |
| `ls -lh`   | Show file sizes in human-readable format         |
| `ls -lah`  | Detailed listing, including hidden files         |
| `ls -R`    | List contents recursively                        |
| `ls -lt`   | Sort by modification time, newest first          |
| `ls -ltr`  | Sort by modification time, oldest first          |
| `ls -lS`   | Sort by file size, largest first                 |
| `ls -r`    | Reverse the sorting order                        |
| `ls -d */` | List directories only (in the current directory) |
| `ls -i`    | Display inode numbers                            |
| `ls -1`    | Display one entry per line                       |

Example:

```
$ ls -lah
```

Possible output:

```
drwxr-xr-x  5 k4n0ng k4n0ng 4.0K Nov  4 10:00 .
drwxr-xr-x 20 root   root   4.0K Nov  4 09:00 ..
-rw-r--r--  1 k4n0ng k4n0ng  120 Nov  4 10:00 notes.txt
drwxr-xr-x  2 k4n0ng k4n0ng 4.0K Nov  4 10:00 Documents
```

### Understanding `ls -l`

Example:

```
-rw-r--r-- 1 k4n0ng k4n0ng 120 Nov 4 10:00 notes.txt
```

| Field                     | Value         | Explanation                      |
| ------------------------- | ------------- | -------------------------------- |
| File type and permissions | `-rw-r--r--`  | Regular file and its permissions |
| Hard link count           | `1`           | Number of hard links             |
| Owner                     | `k4n0ng`      | File owner                       |
| Group                     | `k4n0ng`      | Associated group                 |
| Size                      | `120`         | File size in bytes               |
| Date                      | `Nov 4 10:00` | Last modification time           |
| Name                      | `notes.txt`   | File name                        |

## 5. Creating Directories

### 5.1 `mkdir` — Make Directory

Creates a new directory.

Syntax:

```
mkdir [options] directory_name
```

| Command                         | Description                                          |
| ------------------------------- | ---------------------------------------------------- |
| `mkdir Documents`               | Create one directory                                 |
| `mkdir Folder1 Folder2`         | Create multiple directories                          |
| `mkdir -p Projects/Python/Labs` | Create nested directories, including missing parents |
| `mkdir -v Test`                 | Display a message when creating a directory          |
| `mkdir -m 755 Test`             | Create a directory with permissions `755`            |

Example:

```
$ mkdir Cybersecurity
$ ls
Cybersecurity
```

Create nested directories:

```
mkdir -p Cybersecurity/Networking/Labs
```

Result:

```
Cybersecurity/
└── Networking/
    └── Labs/
```

### 5.2 Creating Multiple Directories with Brace Expansion

```
mkdir -p Projects/{RedTeam,BlueTeam,Networking}
```

Result:

```
Projects/
├── RedTeam/
├── BlueTeam/
└── Networking/
```

You can also create multiple directories with a simple list:

```
mkdir Folder1 Folder2 Folder3
```

## 6. Removing Directories

### 6.1 `rmdir` — Remove Empty Directory

Removes an empty directory.

Syntax:

```
rmdir directory_name
```

Examples:

```
rmdir Test
rmdir EmptyFolder
```

Important: `rmdir` cannot remove a directory containing files or other directories.

### 6.2 `rmdir -p` — Remove Empty Parent Directories

```
rmdir -p Projects/Python/Labs
```

This attempts to remove `Labs`, then `Python`, then `Projects`, provided each is empty.

### 6.3 Difference Between `rmdir` and `rm -r`

| Command         | Description                                                                      |
| --------------- | -------------------------------------------------------------------------------- |
| `rmdir Folder`  | Removes an empty directory                                                       |
| `rm -r Folder`  | Removes a directory and its contents recursively                                 |
| `rm -rf Folder` | Forcefully removes a directory and its contents without interactive confirmation |

Be very careful with `rm -rf`. Linux normally does not move deleted items into a Recycle Bin. Always verify the path before running recursive deletion commands.

## 7. Creating Files

### 7.1 `touch` — Create an Empty File

Creates an empty file if it does not exist.

Syntax:

```
touch filename
```

Examples:

```
touch notes.txt
touch report.pdf
touch script.py
```

Create multiple files:

```
touch file1.txt file2.txt file3.txt
```

Create a file in a specific directory:

```
touch Documents/notes.txt
```

Important: When the file already exists, `touch` updates its access and modification timestamps. It does not erase its content.

### 7.2 Creating a File with `nano`

`nano` is a terminal text editor.

```
nano notes.txt
```

Type your content:

```
Linux File Management
This is my first Linux note.
```

Save and exit:

| Key        | Action           |
| ---------- | ---------------- |
| `Ctrl + O` | Save file        |
| `Enter`    | Confirm filename |
| `Ctrl + X` | Exit nano        |

### 7.3 Creating Files with `echo`

```
echo "Hello Linux" > notes.txt
```

The `>` operator writes content to a file, replacing its existing contents.

Append additional content:

```
echo "Second line" >> notes.txt
```

| Operator | Description                         |
| -------- | ----------------------------------- |
| `>`      | Write or overwrite content          |
| `>>`     | Append content to the end of a file |

## 8. Copying Files and Directories

### 8.1 `cp` — Copy

Copies files and directories.

Syntax:

```
cp [options] source destination
```

Copy a file:

```
cp notes.txt backup.txt
```

Copy a file into another directory:

```
cp notes.txt Documents/
```

Copy multiple files:

```
cp notes.txt report.txt image.png Documents/
```

### Common `cp` Options

| Option | Description                                                   |
| ------ | ------------------------------------------------------------- |
| `-r`   | Copy directories recursively                                  |
| `-R`   | Copy directories recursively                                  |
| `-a`   | Archive mode; preserves attributes while copying recursively  |
| `-i`   | Ask before overwriting                                        |
| `-n`   | Do not overwrite an existing destination                      |
| `-v`   | Display copying operations                                    |
| `-u`   | Copy when the source is newer or the destination is missing   |
| `-p`   | Preserve file mode, ownership where permitted, and timestamps |

Copy a directory:

```
cp -r Projects Backup/
```

Copy and preserve attributes:

```
cp -a Projects Backup/
```

Ask before overwriting:

```
cp -i notes.txt Documents/
```

Display the copy operation:

```
cp -v notes.txt Documents/
```

## 9. Moving and Renaming Files and Directories

### 9.1 `mv` — Move

Moves files and directories to another location.

Syntax:

```
mv [options] source destination
```

Move a file:

```
mv notes.txt Documents/
```

Move multiple files:

```
mv file1.txt file2.txt Documents/
```

Move a directory:

```
mv Projects/ Backup/
```

### 9.2 Renaming Files

You can use `mv` to rename a file.

```
mv oldname.txt newname.txt
```

Example:

```
mv report.txt security-report.txt
```

### 9.3 Renaming Directories

```
mv OldFolder NewFolder
```

### Common `mv` Options

| Option | Description                                                      |
| ------ | ---------------------------------------------------------------- |
| `-i`   | Ask before overwriting                                           |
| `-n`   | Do not overwrite an existing destination                         |
| `-v`   | Display moving operations                                        |
| `-u`   | Move only when the source is newer or the destination is missing |
| `-f`   | Do not prompt before overwriting                                 |

Example:

```
mv -i report.txt Documents/
```

It asks before replacing an existing file with the same name.

## 10. Removing Files

### 10.1 `rm` — Remove

Deletes files.

Syntax:

```
rm [options] filename
```

Examples:

```
rm notes.txt
rm file1.txt file2.txt
```

### Common `rm` Options

| Option | Description                                                                 |
| ------ | --------------------------------------------------------------------------- |
| `-i`   | Ask before every removal                                                    |
| `-I`   | Ask for confirmation before removing multiple files or recursively removing |
| `-f`   | Force removal; ignore nonexistent files and do not prompt                   |
| `-r`   | Remove directories and their contents recursively                           |
| `-R`   | Same recursive behavior as `-r`                                             |
| `-v`   | Display removed files                                                       |
| `-d`   | Remove empty directories                                                    |

Remove a file with confirmation:

```
rm -i notes.txt
```

Remove a directory and its contents:

```
rm -r Projects
```

Forcefully remove a file:

```
rm -f unwanted.txt
```

Remove multiple files:

```
rm file1.txt file2.txt file3.txt
```

Important safety warning

Avoid running commands such as:

```
sudo rm -rf /
```

An incorrect recursive deletion command can destroy important system files and data. Check the directory with `pwd` and `ls` before deleting anything.

## 11. Hidden Files and Directories

Linux uses a leading dot (`.`) to identify hidden files and directories.

Examples:

```
.bashrc
.profile
.ssh/
.config/
```

These files are hidden from a normal `ls` listing.

Show hidden files:

```
ls -a
```

Show hidden files with details:

```
ls -la
```

Create a hidden file:

```
touch .secret.txt
```

Create a hidden directory:

```
mkdir .private
```

Rename a regular file to a hidden file:

```
mv notes.txt .notes.txt
```

Remember: A hidden Linux file is not automatically protected. Its actual security depends on its permissions and ownership.

## 12. Understanding File Types

Linux represents different types of filesystem objects with specific characters.

You can see the type using:

```
ls -l
```

| First Character | File Type        | Description                    |
| --------------- | ---------------- | ------------------------------ |
| `-`             | Regular file     | Text, image, executable, etc.  |
| `d`             | Directory        | Contains files and directories |
| `l`             | Symbolic link    | Points to another path         |
| `c`             | Character device | Character-oriented device      |
| `b`             | Block device     | Block-oriented storage device  |
| `p`             | Named pipe       | FIFO communication object      |
| `s`             | Socket           | Communication endpoint         |

Example:

```
-rw-r--r--  notes.txt
drwxr-xr-x  Documents
lrwxrwxrwx  shortcut -> notes.txt
```

### 12.1 `file` — Identify File Type

Determines the type of a file based on its contents and metadata.

```
file notes.txt
file image.png
file script.py
```

Example output:

```
notes.txt: ASCII text
image.png: PNG image data
script.py: Python script, ASCII text executable
```

Note that a filename extension alone does not guarantee the actual file type.

## 13. File and Directory Information

### 13.1 `stat` — Display Detailed Information

Displays detailed metadata about a file or directory.

```
stat notes.txt
```

Information includes:

- File size
- File type
- Permissions
- Owner and group
- Inode number
- Access time
- Modification time
- Status change time

### 13.2 `du` — Disk Usage

Displays how much disk space files and directories consume.

| Command               | Description                            |
| --------------------- | -------------------------------------- |
| `du file.txt`         | Display file disk usage                |
| `du -h file.txt`      | Human-readable output                  |
| `du -sh Documents/`   | Show total directory size              |
| `du -h --max-depth=1` | Show usage of immediate subdirectories |
| `du -ah`              | Show usage for files and directories   |

Example:

```
du -sh Downloads/
```

Possible output:

```
2.5G    Downloads/
```

### 13.3 `df` — Disk Filesystem Usage

Displays available and used space on mounted filesystems.

```
df -h
```

| Option | Description             |
| ------ | ----------------------- |
| `-h`   | Human-readable sizes    |
| `-T`   | Display filesystem type |
| `-i`   | Display inode usage     |

Example:

```
df -h
df -Th
```

Difference between `du` and `df`:

| Command | Purpose                                   |
| ------- | ----------------------------------------- |
| `du`    | Shows space used by files and directories |
| `df`    | Shows used and available filesystem space |

## 14. Wildcards — Working with Multiple Files

Wildcards allow you to match multiple filenames.

| Wildcard | Meaning                            | Example         |
| -------- | ---------------------------------- | --------------- |
| `*`      | Matches zero or more characters    | `*.txt`         |
| `?`      | Matches exactly one character      | `file?.txt`     |
| `[abc]`  | Matches one character from the set | `file[123].txt` |
| `[0-9]`  | Matches one digit                  | `file[0-9].txt` |
| `[a-z]`  | Matches one lowercase letter       | `[a-z]*.txt`    |

Examples:

List all `.txt` files:

```
ls *.txt
```

Copy all `.txt` files:

```
cp *.txt Backup/
```

Remove all `.log` files in the current directory:

```
rm -i *.log
```

Find files with one character before `.txt`:

```
ls file?.txt
```

Important: In Bash, `*` normally does not match hidden filenames that begin with `.`.

## 15. Links in Linux

Linux supports two important types of links:

1. Hard links
2. Symbolic links (soft links)

### 15.1 Hard Link

A hard link is another directory entry referring to the same underlying inode as the original file.

Syntax:

```
ln original.txt hardlink.txt
```

Example:

```
echo "Linux Security" > original.txt

ln original.txt hardlink.txt
```

Now both names refer to the same file data.

Check inode numbers:

```
ls -li
```

Both files should show the same inode number.

Characteristics:

- Refers to the same inode.
- Both names access the same data.
- Normally cannot be created across different filesystems.
- Creating hard links to directories is generally prohibited for ordinary users.

### 15.2 Symbolic Link (Soft Link)

A symbolic link points to the path of another file or directory.

Syntax:

```
ln -s target link_name
```

Example:

```
ln -s original.txt shortcut.txt
```

Check the link:

```
ls -l
```

Possible output:

```
shortcut.txt -> original.txt
```

Create a symbolic link to a directory:

```
ln -s /home/k4n0ng/Documents Documents_Link
```

Characteristics:

- Points to a pathname.
- Can link to files or directories.
- Can cross filesystem boundaries.
- Can become broken if its target is moved or deleted.

### Hard Link vs Symbolic Link

| Feature          | Hard Link                                         | Symbolic Link          |
| ---------------- | ------------------------------------------------- | ---------------------- |
| Inode            | Same inode as target                              | Has its own inode      |
| Points to        | Underlying file                                   | Pathname               |
| Cross filesystem | No                                                | Yes                    |
| Directory links  | Normally prohibited                               | Supported              |
| Target deleted   | Data remains accessible through another hard link | Link may become broken |
| Command          | `ln`                                              | `ln -s`                |

## 16. File and Directory Permissions

Permissions control who can read, modify, or access files and directories.

You can view permissions using:

```
ls -l
```

Example:

```
-rwxr-xr-- 1 k4n0ng k4n0ng 120 Nov 4 10:00 script.sh
```

### 16.1 Permission Types

| Permission | Symbol | Numeric Value | Meaning for Files           | Meaning for Directories                                           |
| ---------- | ------ | ------------- | --------------------------- | ----------------------------------------------------------------- |
| Read       | `r`    | 4             | Read file contents          | List directory entries                                            |
| Write      | `w`    | 2             | Modify file contents        | Create, delete, and rename entries, subject to other restrictions |
| Execute    | `x`    | 1             | Execute a program or script | Traverse/access entries by name                                   |

### 16.2 Permission Groups

The permissions are divided into three groups:

| Group | Meaning      |
| ----- | ------------ |
| `u`   | User (owner) |
| `g`   | Group        |
| `o`   | Others       |
| `a`   | All          |

Example:

```
-rwxr-xr--
```

| Group  | Permission | Numeric |
| ------ | ---------- | ------- |
| Owner  | `rwx`      | 7       |
| Group  | `r-x`      | 5       |
| Others | `r--`      | 4       |

Therefore:

```
chmod 754 script.sh
```

### 16.3 `chmod` — Change Permissions

Numeric method:

```
chmod 755 script.sh
chmod 644 notes.txt
chmod 700 private.sh
```

| Permission | Meaning                                                           |
| ---------- | ----------------------------------------------------------------- |
| `777`      | Everyone has read, write, and execute                             |
| `755`      | Owner has full permission; group and others have read and execute |
| `700`      | Only the owner has full permission                                |
| `644`      | Owner can read and write; group and others can read               |
| `600`      | Only owner can read and write                                     |

Symbolic method:

```
chmod u+x script.sh
chmod g+w notes.txt
chmod o-r notes.txt
chmod a+r file.txt
```

| Command           | Description                             |
| ----------------- | --------------------------------------- |
| `chmod u+x file`  | Add execute permission to owner         |
| `chmod g+w file`  | Add write permission to group           |
| `chmod o-r file`  | Remove read permission from others      |
| `chmod a+r file`  | Add read permission to everyone         |
| `chmod u=rw file` | Set owner permissions to read and write |

Recursive permission change:

```
chmod -R 755 Projects/
```

Be careful with recursive permission changes. Files and directories frequently need different permissions.

### 16.4 `chown` — Change Ownership

Changes the owner of a file or directory.

```
sudo chown username notes.txt
```

Change both owner and group:

```
sudo chown username:groupname notes.txt
```

Change ownership recursively:

```
sudo chown -R username:groupname Projects/
```

### 16.5 `chgrp` — Change Group Ownership

```
sudo chgrp developers notes.txt
```

Change the group of a directory recursively:

```
sudo chgrp -R developers Projects/
```

## 17. Handling Filenames with Spaces and Special Characters

Linux allows spaces and many special characters in filenames.

For example:

```
my report.txt
security notes.txt
```

Use quotation marks to handle spaces:

```
touch "my report.txt"
```

Copy the file:

```
cp "my report.txt" Documents/
```

Rename it:

```
mv "my report.txt" report.txt
```

You can also escape spaces using a backslash:

```
touch my\ report.txt
```

### Filenames Starting with a Hyphen

A filename may start with `-`, which can be mistaken for a command option.

Use `--` to mark the end of command options:

```
rm -- -notes.txt
```

tree

The `-i` option asks for confirmation during deletion.
